# `app.*` data, data spaces and panels

`app.*` is the bot's shared data — ordinary variables that scripts, tokens, `list_buttons` and Mini Apps read. A **panel** is the owner's page over a piece of it, in the bot's «Дані» menu.

## Data spaces

A bot may keep several independent copies of the same data: two shops, a booking per branch. Each copy is a **data space** named by a `scope`: space `shafa` keeps its data under `app.shafa.*`, the main space under `app.*` itself. A template installed a second time under another name, or a panel created with «Нові дані», opens a new space.

**Write `app.*` in a document and pass `scope` in the write body** — the server re-roots every `app.` to `app.<scope>.` and fills `{{app_query}}`. Export with `?scope=<scope>` to get portable `app.*` back. `GET /mini_apps` and `GET /panels` show which spaces the bot has.

Rules for data flows read: lists of flat objects, numbers as numbers, rich text as an `html` + `text` pair, depth ≤ 5. Every object in a list gets an `_id` from the server on save (never set or change it); a stable `id` of your own is still the right thing for deep links and lookups.

`seed_app_variables` in a document writes initial values only where the space has none — the owner's data afterwards. Its keys are top-level names; nest with objects (`{"veres": {"squad": …}}`), not with dotted keys.

## Panels

A panel is one of three kinds:

| kind | `definition` | what the owner gets |
|---|---|---|
| Storefront («Вітрина») | `{"editor": "catalog"}` — nothing else | product cards over `app.catalog`, the orders from `app.orders` as a table, the `shop` Mini App's preview and look |
| Schedule («Розклад») | `{"editor": "schedule"}` — nothing else | calendars with working hours and bookings over `app.calendars`, the `calendar` and `week` Mini Apps' preview and look |
| Table | `{"source": …, "columns": …}` (below) | a table over one list of your own |

A Storefront or a Schedule is the owner's page for that data — do not build a table panel over `catalog`, `orders` or `calendars`. Before building a shop or a booking yourself, offer the owner the template (SKILL.md § Templates).

Key a panel by what it shows, unique in the bot: `catalog`, `schedule`, `orders`; in a data space prefix the space (`shafa_catalog`), as Lanka does. A panel's `scope` is its data space.

### Storefront data

```
app.catalog = [{ "id": "sneakers", "name": "Кросівки", "category": "Взуття", "price": 1200, "image": "https://…", "description_html": "<p>…</p>", "description_text": "…" }]
app.orders  = [{ "id": "…", "at": "2026-10-13T10:00:00+03:00", "name": "…", "username": "…", "user_id": "…", "phone": "…", "items": [{ "name": "…", "price": 1200, "qty": 1 }], "total": 1200, "status": "new" | "done" }]
```

`id` — a stable string (it travels in deep links as the data after the dash); `category` is optional and becomes a filter in the Mini App; `image` is an uploaded url (SKILL.md, `POST /uploads`). The «Замовлення» tab reads exactly these order fields; a flow that records orders writes them so.

### Schedule data

```
app.calendars = [{
  "id": "ivanenko", "name": "Марія Іваненко", "description": "Терапевт",
  "schedule": { "slot_minutes": 60, "days": { "2026-10-14": [{ "start": "09:00", "end": "13:00" }] } },
  "slots": [{ "date": "2026-10-14", "time": "09:00", "status": "free" }]
}]
```

One calendar per person, room or service clients book. `slots` are generated by the editor from `schedule` (one per `slot_minutes` that ends inside an interval); a day absent from `days` is a day off. A booking flow marks a slot with `update_where` over the calendar's `slots`: `status: "booked"` plus `by` (the client's name), `username`, `user_id`, `calendar_id`, `calendar`, and optionally `note` (the client's comment). Freeing a slot sets `status` back to `"free"`. The owner's private note is `owner_note` — never write it.

### Table panels

A table is the owner's way to see and edit a list of your own — requests, registrations, a queue. It has filters, a status changed in place and buttons that act on a record. Build it instead of telling the owner to read the JSON in «Дані» → «Змінні». One per list, keyed; the owner can edit it afterwards («Дані» → «Панелі»), so every field below has a control there — use only these.

```json
{
  "key": "requests",
  "title": "Заявки",
  "icon": "fas fa-receipt",
  "definition": {
    "source": "requests",
    "visitor": "user_id",
    "sort": { "name": "at", "direction": "desc" },
    "removable": true,
    "columns": [
      { "name": "at", "title": "Коли", "type": "datetime", "sortable": true },
      { "name": "name", "title": "Клієнт", "type": "visitor" },
      { "name": "items", "title": "Склад", "type": "list", "item": "###item.name### ×###item.qty###" },
      { "name": "total", "title": "Сума", "type": "money", "unit": "грн", "sortable": true, "halign": "right" },
      { "name": "status", "title": "Статус", "type": "status", "editable": true, "filter": true,
        "options": [{ "value": "new", "label": "Нова", "theme": "primary" }, { "value": "done", "label": "Виконано", "theme": "grey" }] }
    ],
    "actions": [
      { "key": "confirm", "label": "Підтвердити", "bulk": true, "confirm": false,
        "show_when": { "name": "status", "in": ["new"] },
        "script": "record.status = \"confirmed\"",
        "flow": "request_confirmed" }
    ]
  }
}
```

- `source` — the path under the panel's scope to a list of objects: a key (`requests`) or a dotted path (`doctors.list`). Every object in a list gets an `_id` from the server when the bot's data is saved — that is a record's identity; your own `id` field stays an ordinary field. A list inside the items of another list (`calendars[].slots`) cannot be a panel.
- `visitor` — the record field with the visitor's Telegram id (`platform.user_id` when the flow wrote it). Actions need it: they run as that visitor.
- `columns[].type`: `text`, `number`, `money` (+`unit`), `datetime` (ISO strings), `status` (+`options` with `value`, `label`, `theme` ∈ `grey|primary|warning|danger`; `editable` lets the owner change it in the table), `visitor` (the name, with `@username` from the record's `username`), `list` (+`item`: one item as text with its fields as `###item.<field>###` tokens, one item per line, or on one line comma-separated with `inline: true`; without a pattern, plain values as they are and objects by their first text field). `sortable`, `filter`, `width`, `halign` as on a table column.
- `actions[]` — a button on a record; `bulk` offers it over selected records; `confirm` asks first; `show_when` keeps it to records whose field has one of the values. What it does: `script` (safe-expr run for the record's visitor; the record is `record.*` — `record.status = "done"` changes it in the list — and read-only as `params.record`; `user.*` is theirs, `app.*` the panel's scope) and/or `flow` (a flow of the document by key — in the API body as `flow_id` — started for the visitor with the record in `session.record`). A script cannot send a message; use the flow for that.

Through the API the same object goes in `{"panel": …}` with `scope` beside `key` (omit it for the main space) and `flow_id` instead of `flow`. A Storefront or a Schedule goes in a document instead (format.md: `panels` with `mini_apps` and `seed_app_variables`), so its Mini Apps and empty lists come with it.

## Deep links

Every flow is reachable by `https://t.me/{{bot.username}}?start=<payload>`, no setup. The payload names the flow by its link key — `{{flow.<key>}}` in a document — or by its command (`?start=shop` opens `/shop`), and may carry data after a dash: `?start={{flow.card}}-sneakers` opens `card` with `platform.start_param = "sneakers"`, which the conversation keeps as `session.start_param`. A payload naming nothing opens `/start`. Internal flows cannot be linked to.

```
"script": "price_list = join(map(app.catalog, \"<a href='https://t.me/{{bot.username}}?start={{flow.card}}-\" + item.id + \"'>\" + item.name + \"</a>\"), \"\\n\")"
```
